# dida v0.1.0

Date: 2026-09-25

首个发布版本. dida 把滴答清单的能力从 MCP 搬到命令行, 让 agent 与脚本可以直接调用: 通道走滴答官方 MCP 端点, 认证只需要一个 API 口令, 交付物是单个 Go 二进制, 没有任何运行时依赖.

能力边界需要先说清楚. 官方 MCP 通道没有覆盖附件, 回收站, 统计报表, 模板与共享协作, 这些能力只存在于网页私有接口, 本版本无法提供, 详见文末的 Known Limitations.

## Highlights

- 把官方 55 个工具全部接到命令行: 其中 72 条命令契约做了结构化封装, 覆盖清单, 任务, 评论, 习惯, 专注, 标签, 清单分组, 看板列与倒数日, 剩下的用 `dida tool call` 直通.
- 拿到稳定的机器可读输出: stdout 恒为 JSON 信封, 成功与失败同一形状, 错误带分类和可以直接照做的 hint, 退出码细分到 7 种; 日志只写 stderr, 管道不会被日志打断.
- 执行前先看清楚: 所有写命令都支持 `--dry-run`, 先输出将要发出的请求体, 再决定是否真正执行.
- 需要时能被真正约束住: `read_only` 与 `non_destructive` 两道闸门写在配置里, 命令行无法关闭.
- 不用猜参数: `dida skill` 给出随二进制分发的使用指南, `dida schema` 与 `dida tool` 给出本 CLI 与官方工具各自的完整契约.

## Upgrade Notes

这是首个发布版本, 不存在需要迁移的旧版本与旧配置.

1. 安装:

   ```shell
   go install github.com/azazo1/dida-cli/cmd/dida@latest
   ```

2. 在滴答清单网页版进入头像 > 设置 > 账户与安全, 复制 API 口令, 用管道写入本地:

   ```shell
   printf 'dp_你的口令' | dida auth login
   ```

3. 验证安装与认证:

   ```shell
   dida doctor
   dida view today --compact
   ```

   `dida doctor` 报出口令状态, 端点连通性与官方工具总数, 退出码 0 表示全部检查通过.

## Features

**通道与认证**

- 通过 `https://mcp.dida365.com` 接入, 只需要 `dp_` 开头的 API 口令, 不需要交出浏览器登录态, 也不需要注册 OAuth 应用.
- 口令只从 stdin 读入, 落在本地配置文件并收紧到 `0600`, 不经过命令行参数, 不会留在 shell 历史里; `dida auth status` 只输出脱敏预览.
- 配置目录默认 `~/.config/dida-cli`, 可用 `DIDA_CONFIG_DIR` 覆盖, 便于多账号或隔离测试.

**命令覆盖**

- 清单: `project list / get / data / members / create / update`.
- 任务: `task list / get / create / update / complete / delete / move / search / checklist-done / assign / unassign / batch-add / batch-update / complete-project`.
- 习惯, 专注, 标签, 清单分组, 看板列, 评论, 倒数日各自成组, 读写齐备.
- 便捷视图: `view today / tomorrow / next / upcoming / last7day / overdue / inbox / completed / query`.
- 只给任务 id 时自动反查所属清单, 不必先去查 project id.

**安全约束**

- `read_only` 拒绝全部 30 个写工具, 来源可以是配置项, 环境变量 `DIDA_READ_ONLY` 或参数 `--read-only`.
- `non_destructive` 拒绝 5 个删除类工具, 但放行创建与更新.
- 两道闸门只收紧不放松: 配置里打开后, 命令行无法把它关掉, agent 也就无法自我提权.
- 判定依据是官方工具的 `readOnlyHint` 与 `destructiveHint` 注解, 不是本地维护的静态名单, 官方调整工具属性时会自动跟随.
- 破坏性操作默认要求 `--yes`, 缺少时以退出码 6 拒绝, 并提示先用 `--dry-run` 核对.

**输出与自省**

- JSON 信封统一为 `{ok, command, data, error, meta}`; 失败时 `error.type` 给出分类, `error.hint` 给出可执行的补救建议.
- 退出码: 0 成功, 1 通用错误, 2 用法错误, 3 认证失败, 4 资源不存在, 5 上游错误, 6 缺少确认, 7 被本地闸门拦下.
- `--compact` 裁剪字段以节省 token, `--format table` 给人工阅读.
- `dida schema list / show` 给出 72 条命令契约; `dida tool list / show` 给出官方工具的原始契约与读写属性.
- 官方把业务失败包在 `structuredContent` 里返回时, 会被提升为退出码 5 的上游错误, 不会静默成功.

**参数与时间**

- 具名参数与完整参数两种模式: 常用场景写 flag, 参数多或结构嵌套时用 `--body-json`, 取值为 JSON 文本, `-` 表示从 stdin 读, `@文件` 表示从文件读.
- 时间字段接受 `2026-09-25`, `2026-09-25 09:00`, RFC3339, 以及 `today` / `tomorrow` / `+3d` / `-1w` 这类相对写法, 统一按配置时区归一化成服务端要求的线格式.
- 读路径的相对时间由官方服务端解析, 与账号时区一致, 客户端只负责透传.

**配置**

- 配置文件带版本号字段, 版本升级时按 migration 迁移, 不依赖幂等修补.
- 工具目录可本地缓存, 减少重复往返; 缓存只保存工具契约, 不含账号数据.

**构建与分发**

- 单 Go 二进制, 无运行时依赖.
- CI 在 linux, macOS, Windows 的 x86_64 与 aarch64 六个原生 runner 上分别构建, 归档前跑 `--version` 冒烟校验, 发布时额外产出 deb 与 rpm.
- 发布构建的版本号自动生成: 恰好停在 tag 上时显示该 tag, 非 tag commit 追加 7 位短 hash, 工作区有未提交改动时改用 `^` 分隔, 日常开发构建显示 `dev-build`.

## Known Limitations

- 官方 MCP 通道没有附件, 回收站, 统计报表, 模板与共享协作, 需要这些能力时只能用网页端.
- 官方通道没有删除习惯的工具, 因此 `habit create` 不可撤销.
- `view overdue` 官方没有对应工具, 是本地按截止时间筛选出来的, 结果准确性取决于服务端返回的未完成任务是否完整.
- 搜索是最终一致而非实时: 刚创建的任务可能短时间内搜不到, 按 id 读取不受影响.
- 官方自身的限制: `focus list` 的时间范围不得超过一个月, `focus create` 的结束时间不能晚于当前时刻, `task complete-project` 单次最多 20 个任务.
- `tag update` 不能修改标签名, 改名需要用 `tag rename`.
